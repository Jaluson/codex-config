# 开发规范治理

本目录只维护项目级开发规范的治理原则，不穷举空格、注释模板、类名或日志格式。可执行的格式和风格规则优先交给项目已有的格式化器、Lint、类型检查、测试、构建和架构检查工具。

## 规则来源优先级

按以下顺序处理冲突：

1. 用户明确要求、安全要求和已有公共契约。
2. 项目根目录 `AGENTS.md`、构建配置、CI 配置和已提交的质量工具配置。
3. 本目录的工程原则。
4. 框架默认习惯和 Agent 通用知识。

没有可靠来源时，不把个人偏好写成规则。既有代码样例只能作为低置信度参考，不能单独产生阻断项。

## 必须保持的工程原则

- 不破坏已确认的 API、数据库、消息、配置和序列化契约。
- 输入校验、权限判断、异常转换、事务边界和异步行为必须有明确责任边界。
- 不把密钥、令牌、生产数据或敏感信息写入代码、日志和 Artifact。
- 变更必须有与风险匹配的测试或其他可验证证据。
- 只修改任务范围内的文件，不用全量格式化或无关重排掩盖实际变更。
- 未执行、失败或受环境阻塞的检查必须如实记录，不能报告为通过。

## 门禁级别

- **阻断**：明确规则或已配置工具失败；安全、契约、正确性、数据一致性问题；必要验证无法完成。
- **告警**：规范目录或可选工具缺失；仅由既有样例推断出的风格差异；非关键 `SHOULD` 偏差。
- **未知**：没有充分证据，不报告为违规。

统一检查器会记录每项检查的来源、命令、退出码、证据和结论。新增具体风格规则时，应先加入项目工具配置或本目录，再由检查器执行或引用。
