# Vue 3 前端开发规范

## 1. 适用范围和版本

本规范适用于 Vue 3 + TypeScript + Vite 单页应用。Vue、Vite、TypeScript、Vue Router、Pinia、测试工具和 Node 版本以目标项目配置为准；包管理器使用 `.dev-env.yaml` 和 `package.json` 中已声明的实际工具。

不得因为本文档存在就直接升级前端框架、构建工具或依赖。升级应单独记录兼容性变化、构建产物、浏览器支持、测试和回滚方式。

## 2. 组件和数据流

- 组件边界应围绕可复用职责、业务场景或视觉区域建立；页面编排、展示组件和数据访问职责应可区分。
- Props、Emits、插槽和暴露方法形成组件契约，必须定义清楚类型、必填性、默认值、事件语义和失败行为。
- 子组件通过事件表达意图，不能偷偷修改父组件对象或依赖未声明的全局状态。
- 可复用的状态转换、异步流程和副作用优先提取为 composable；与单个页面强绑定的逻辑不强行抽象。
- Store 只保存跨页面或跨组件需要共享的状态；短生命周期的表单、弹窗和局部加载状态留在组件边界。
- 服务端状态、缓存状态、用户输入和纯 UI 状态应区分所有权，避免多个来源同时写入同一事实。

## 3. TypeScript 和 API 边界

- API 请求和响应必须有明确类型；无法确认的外部数据在边界解析和校验，不能通过大范围 `any` 隐藏不确定性。
- API 客户端负责协议调用、序列化和错误转换；组件负责展示状态，不在多个页面复制请求细节。
- 接口类型变化必须与后端契约和接口文档同步，尤其是字段可选性、空值、分页、状态码和错误结构。
- 用户输入、URL 参数、Storage、第三方脚本和后端响应都视为不可信来源。
- 类型断言必须说明为什么安全；不能用 `as`、非空断言或关闭检查来绕过未处理的空值和错误路径。

## 4. 路由、权限和交互状态

- 路由守卫可以改善导航体验，但不能替代后端鉴权；前端隐藏按钮不能作为安全边界。
- 路由参数、查询参数和回退路径必须校验，避免不可信 URL、开放重定向和越权展示。
- 异步交互至少明确初始、加载、成功、空数据、失败、重试和取消状态；避免请求竞态覆盖较新的结果。
- 表单必须明确校验时机、错误位置、提交中状态、重复提交、服务端错误和恢复方式。
- 破坏性操作应有清楚的确认、幂等或防重复机制，并在结果明确后更新本地状态。
- 全局错误处理不能吞掉局部上下文；用户提示应安全、可理解，调试细节写入受控日志而非界面。

## 5. 安全和可访问性

- 禁止把未经净化的内容直接交给 `v-html` 或等效 HTML 注入入口。
- 不可信 URL、下载地址、图片地址、iframe 地址和第三方脚本必须校验协议、来源和用途。
- 令牌和敏感数据的存储位置必须符合目标项目安全设计；不写入日志、错误上报、URL、查询字符串或不必要的持久化存储。
- 前端校验只用于体验，后端仍必须重新校验输入、权限和业务规则。
- 交互组件必须支持键盘操作、焦点管理、语义化标签和可读的错误提示；颜色不能是传达状态的唯一方式。
- 加载、错误、空状态和动态更新应对辅助技术可理解，避免焦点丢失和不可关闭的模态层。

## 6. 性能和资源生命周期

- 性能优化先记录首屏、交互延迟、请求耗时、包体或内存基线，再定位实际瓶颈。
- 按路由和功能边界进行合理的代码分割；不为了微小收益制造难以调试的动态加载。
- 长列表使用适合的数据分页或虚拟化方案；避免无界渲染、重复请求和不必要的深层响应式依赖。
- 组件卸载时清理定时器、事件监听、订阅、AbortController 和其他外部资源。
- 图片、字体、第三方脚本和缓存策略应考虑体积、来源、失败回退和隐私影响。
- 不通过全局缓存或持久化保存无法失效的用户数据；缓存必须说明生命周期和一致性策略。

## 7. 测试和前端验证

- 组件测试关注用户可见行为、交互、状态转换和错误路径，不依赖脆弱的内部实现细节。
- Composable、Store、路由守卫和 API 客户端应根据风险补充单元或集成测试。
- 至少覆盖表单校验、加载/失败/重试、权限展示、空数据、重复操作和接口错误。
- 测试不依赖真实网络、固定机器时间、随机顺序或未声明的全局状态；外部依赖使用可控替身。
- 执行目标项目已有的 lint、类型检查、测试和构建脚本，只使用 `package.json` 中真实存在的脚本。

## 8. 前端验证清单

- 是否清楚组件契约、状态所有权和 API 数据边界？
- 是否覆盖空值、加载、失败、重试、取消、重复提交和竞态请求？
- 是否检查前端权限仅用于展示、后端仍执行真实授权？
- 是否排查 `v-html`、不可信 URL、令牌持久化和敏感日志？
- 是否验证键盘、焦点、语义、错误提示和动态内容的可访问性？
- 是否执行项目已有的格式、Lint、类型、测试和构建检查；未执行项是否如实记录？
