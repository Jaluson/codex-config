# 安全可靠性与发布规范

## 1. 安全边界

所有来自用户、浏览器、外部服务、消息、文件、环境变量、配置和历史数据的输入都视为不可信。安全要求必须在真正执行操作的服务端或受控边界生效，不能只依赖前端展示。

## 2. 密钥和敏感数据

- 密钥、令牌、密码、私钥、生产数据和个人敏感信息不得写入源码、配置示例、日志、测试夹具、接口文档或 Artifact。
- 示例使用占位值；测试使用合成或脱敏数据，且数据范围与生命周期可控。
- 令牌不放入 URL、查询字符串、异常消息、前端错误上报或不必要的持久化存储。
- 日志、指标、追踪和调试输出必须经过脱敏；高基数用户标识不能直接作为指标标签。
- 发现疑似凭据泄露时停止扩散、记录范围并按项目安全流程轮换和清理；不能只删除当前文件中的字符串。

## 3. 输入、输出和权限

- 在边界校验类型、长度、范围、格式、编码、文件大小和资源数量；业务层保护领域不变量。
- 对 SQL、命令、路径、模板、HTML、URL、文件名和序列化数据使用上下文适配的安全 API，不能依赖字符串拼接。
- 所有修改、导出、删除和跨租户查询都必须服务端验证身份、权限、资源所有权和业务状态。
- 输出只包含调用方需要的字段；错误不泄露堆栈、SQL、内部路径、配置和资源存在性信息。
- 前端禁止把不可信内容直接交给 `v-html` 或等效注入入口；不可信 URL 必须校验协议和来源。

## 4. 路径、文件和外部调用

- 用户可控路径必须解析后验证位于允许根目录内，并拒绝绝对路径、路径穿越和未经允许的符号链接。
- 上传、下载、导出和解压必须限制大小、类型、数量、目标目录和生命周期。
- 外部 HTTP、RPC、数据库、消息和文件操作必须有超时、取消/中断、错误分类和最小权限。
- 重试只用于可重试错误，并配置上限、退避、幂等保护和最终失败处理；不能让重试放大写入或雪崩。
- 第三方返回的数据必须在边界转换和校验；外部系统成功不等于本地事务已成功。

## 5. 依赖和供应链

- 新增或升级依赖必须有需求、版本来源、许可证/安全影响、兼容性和回滚记录。
- 构建脚本、安装脚本、代码生成和外部命令只能执行受控参数和工作目录。
- 不运行来源不明的脚本，不为通过检查绕过锁文件、签名、权限或安全扫描。
- 升级框架、JDK、Node、构建插件和解析器时，检查废弃行为、默认安全策略和生成产物变化。

## 6. 可靠性和可观测性

- 关键业务操作必须定义成功、失败、重试、重复请求、超时、取消和补偿语义。
- 事务、消息确认、缓存更新和外部副作用的顺序必须可解释；必要时采用幂等键、Outbox、补偿或人工处理，但不得只写机制名称。
- 关键链路记录关联标识、结果、耗时和失败原因；记录内容必须脱敏且可按权限访问。
- 监控应覆盖错误率、延迟、吞吐、资源使用、队列积压、重试和依赖可用性；阈值和告警责任应在项目运行文档中明确。
- 性能问题先建立基线和复现条件，再进行优化；不能以无限线程、缓存、连接或重试掩盖容量问题。

## 7. 数据迁移和发布

- 数据库、消息、配置和缓存变更必须说明旧版本兼容、部署顺序、回填/双写、验证、清理和恢复方式。
- 破坏性迁移拆成可观察的小步骤；在确认新代码和数据都稳定前保留回退路径。
- 发布前核对构建产物、配置、权限、迁移、接口文档、监控、告警和回滚入口。
- 高风险变更应采用分批、灰度或可快速关闭的开关，具体方式以目标项目发布能力为准。
- 回滚代码不一定能回滚数据；交付报告必须分别说明代码回滚、配置回滚、数据恢复和外部副作用处理。

## 8. 安全事件和异常处理

- 发现安全问题、数据泄露、错误权限或不可逆数据损坏时，优先停止进一步扩散并保留最小必要证据。
- 不在普通日志、Issue、PR 或 Artifact 中公开敏感细节；按项目安全渠道升级。
- 事件修复必须包含根因、影响范围、受影响契约、短期缓解、长期修复、验证和防回归测试。
- 不能确认影响范围时报告未知并提高风险等级，不用“暂未发现”替代完整调查。
