# 工程治理与交付规范

## 1. 目标和适用范围

本规范定义工程变更从提出到交付的最小可追溯流程，适用于功能开发、缺陷修复、重构、测试补充、性能优化、升级迁移和代码审查。

它不替代目标项目的业务规则、架构文档、构建配置或发布制度；已有来源优先，并在交付记录中引用。

## 2. 角色和责任

| 角色 | 责任 |
| --- | --- |
| 需求/业务负责人 | 明确目标、范围、验收条件、优先级和风险接受人 |
| 实施者 | 收集证据、保护契约、完成实现和验证，报告未执行项 |
| 审查者 | 基于变更证据检查正确性、安全性、兼容性、性能和可维护性 |
| Agent | 遵守用户和仓库规则，保留证据，不扩大范围或隐瞒阻塞 |
| 维护者 | 维护规范、工具、Registry、Skill 和模板的一致性 |

同一人可以承担多个角色，但需求确认、实施判断和最终审查结论必须在记录中区分。

## 3. 标准流程

### 3.1 明确范围和现状

- 记录目标、成功标准、非目标、影响模块和约束，确认任务类型与风险。
- 识别公共 API、数据库、消息、配置、权限、外部服务、缓存和用户数据影响；不清楚且会改变实现方向的问题标为待确认或阻塞。
- 先读取 `AGENTS.md`、`.dev-env.yaml`、规范入口、构建/测试配置和相关契约；检查 `git status`、目标 diff、用户已有修改和未跟踪文件。
- 以代码、测试、配置、日志、指标和外部系统状态为事实来源；样例和一般经验只能作为低置信度建议。

### 3.2 设计和实现

- 先描述输入、输出、错误、权限、状态变化、事务边界、异步行为和兼容性，再决定实现结构。
- 对外部边界明确校验、鉴权、异常转换、事务提交、重试、指标和回滚责任；涉及 API、数据、消息、配置或序列化时明确兼容策略和文档位置。
- 只修改任务范围内文件，采用最小、可审查的变更；不覆盖用户已有修改，不混入无关格式化、批量重命名或依赖升级。
- 文本使用 UTF-8；删除、迁移、部署、外部写入或数据操作前确认精确目标、权限、幂等性和恢复方式。

### 3.3 验证、审查和交付

- 按风险选择最小充分的测试，覆盖成功、失败、边界、权限和回归路径；先执行通用检查，再执行已配置的质量工具。
- 检查前确认规范来源和工具未变；需要时重新计算规范指纹。未执行、失败、超时或环境缺失必须单独记录。
- 交付前核对代码、测试、接口文档、数据库/消息迁移、配置、安全、监控和发布说明是否同步。
- 交付结论仅覆盖已有证据的范围；不得把推断或未执行检查写成通过。

## 4. 风险分级

| 风险 | 典型范围 | 最低验证要求 |
| --- | --- | --- |
| 低 | 纯文档、内部重命名、无行为变化的局部重构 | UTF-8、diff 检查、相关静态检查或审查证据 |
| 中 | 业务逻辑、组件交互、配置、错误处理、权限展示 | 定向测试、失败/边界场景、相关构建或类型检查 |
| 高 | 公共 API、数据库/消息、鉴权、敏感数据、并发、外部写入、发布配置 | 契约验证、回归测试、迁移/回滚演练或明确的环境阻塞记录 |

按实际影响取最高风险，不因代码行数少而降低公共契约或安全变更的等级。

## 5. 审查要求

审查以实际影响为中心，按正确性、安全、契约、数据一致性、性能容量、可测试性和可维护性的顺序进行。审查开始前确认基准分支、变更范围、工作区状态、相关调用方、文档、测试、迁移、部署配置和外部系统；无法读取的范围必须记录为限制。

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| 阻断 | 安全事故、数据损坏、公共契约破坏、核心功能错误或必要验证缺失 | 修复或由有权限的人明确接受风险后才能交付 |
| 高风险 | 常见路径错误、越权、兼容性回归、严重性能问题或不可恢复副作用 | 默认修复并补充验证 |
| 一般 | 局部正确性、可维护性、测试缺口或可观测性问题 | 应修复；延期时记录原因和影响 |
| 建议 | 不影响当前行为的改进或低置信度风格建议 | 不单独阻断 |

每项发现必须包含位置、事实证据、影响、复现或推理、修复方向和需要补充的测试。具体格式差异只有在项目工具或明确规则支持时才能形成违规。

## 6. 交付和交接

- 变更说明记录目标、范围、非目标、风险、契约影响和回滚方式；提交或 PR 不混入无关变更，确需混合时拆分或说明原因。
- 交付报告列出实际变更、环境和工具版本、执行命令及退出码、未执行/失败/阻塞项、契约文档结论、安全与发布影响、残留风险和后续动作。
- 复杂任务使用已有 Workflow、Skill 和 Artifact；Artifact 记录来源、状态、证据和未完成项。阶段失败时保留原始错误，不删除证据或盲目重试有副作用的操作。
- 模板必须填写真实信息；占位符替换为事实或标记为待确认。Artifact 是交接载体，不替代代码、测试和外部状态证据。

## 7. 完成检查

- [ ] 目标、范围、非目标和风险清楚，相关契约已同步。
- [ ] 必要测试和质量检查已有真实结果，未执行项已公开。
- [ ] 审查发现已修复、接受或明确记录。
- [ ] 已说明代码、配置、数据和外部副作用的回滚或恢复方式。
- [ ] 工作区没有混入任务范围外的变更、密钥、生产数据或未授权生成物。
