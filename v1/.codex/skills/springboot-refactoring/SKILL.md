# Spring Boot 安全重构

## 目标

在可验证的行为基线之上改善结构、可读性、职责边界和可维护性，同时保持 API、消息、数据库、配置、权限、事务和异常语义不变。将重构与新功能、缺陷修复、性能优化和版本升级分开处理。

设计与实现时遵守[通用设计与实现方向](../通用设计与实现方向.md)。

## 工作流程

### 1. 明确不变量和范围

- 先检查 git status、相关 diff、模块结构、公共接口、调用方、测试、配置和部署约定，保留用户已有修改。
- 列出必须保持不变的输入输出、状态码、错误码、事务边界、权限判断、事件契约、序列化形式和数据库语义。
- 执行测试或构建前读取 .dev-env.yaml，使用配置的 Java 和 Maven 路径，仅对当前进程设置环境。
- 若请求同时包含业务规则变化、Bug 修复、性能目标或依赖升级，先拆出明确范围；未获授权时不混入重构。

### 2. 建立行为基线

- 运行现有定向测试，补充能表达关键不变量的测试；没有基线时先记录缺口和风险。
- 检查 Spring Bean 扫描、构造注入、代理、AOP、事务、事件监听、Jackson、JPA 反射和配置绑定，识别重构敏感点。
- 对公共 API、持久化实体、消息 DTO 或配置键，确认调用方和兼容策略后再移动或改名。

### 3. 分步实施重构

- 选择单一结构目标，按小步提交或小批次修改：提取职责、消除重复、调整依赖方向、整理包结构或替换局部实现。
- 保持构造注入和 Bean 生命周期；不要破坏 @Transactional、@Async、@Cacheable、安全拦截器或其他代理边界。
- 保持外部 DTO、实体映射、消息字段、配置键和异常格式；确需兼容适配时保留旧入口并说明淘汰计划。
- 不用全量格式化、无关改名、依赖升级或大范围重排掩盖实际重构。

### 4. 验证行为等价

- 运行单元、Web、数据访问和集成测试，覆盖成功、边界、异常、权限、事务、并发和序列化场景。
- 对 API、数据库或消息有影响的重构，检查生成文档、迁移顺序、查询结果、事件契约和回滚方式。
- 使用 Maven Wrapper；Windows 优先使用 mvnw.cmd。检查 git diff、git diff --check 和变更规模。

## 交付和边界

- 交付重构目标、保持的不变量、结构变化、测试命令和结果、未覆盖风险及后续拆分建议。
- 如果行为基线失败，先判断是既有失败还是重构回归；不得静默删除或放宽失败测试。
- 如果发现真实缺陷，记录为独立问题并按用户授权转入 springboot-bug-fixing。
- 所有新增或修改文本使用 UTF-8；不执行无关的破坏性命令。

## 接口文档门禁

- 若重构改变对外 HTTP/Web API 的路径、方法、参数、响应、状态码、错误、鉴权或兼容行为，调用 `$api-documentation` 更新 `docs/接口文档/${模块}-${功能}.md`；只保留一份当前文档，历史变化写入修订记录。
- 若重构未改变公共接口，在交付结果或当前 run Artifact 中明确记录“无需更新接口文档”。

## 开发规范

- 直接调用本 skill 时，先读取项目根目录 `docs/开发规范/README.md`（存在时）和项目已有质量工具；不凭个人偏好添加风格规则。
- 由 `$orchestrator` 调用时，规范检查由 `development-standards` 阶段统一执行，本 skill 只遵循其报告和本任务专属约束。

## 编排契约

- 由 `$orchestrator` 调用时，按 Workflow Registry 指定的阶段执行，不重复执行其他阶段；直接调用本 skill 时仍执行完整重构流程。
- 支持阶段：`invariants`、`baseline`、`refactor`、`equivalence`、`verify`。
- 读取当前 run 中注册的输入 Artifact，将不变量、基线、变更和等价验证结果写入注册的输出 Artifact；不得使用未声明的路径传递上下文。
- 修改前保护行为基线；发现行为变化或基线失败时保留证据并暂停，不静默放宽测试。
