# 测试与质量门禁规范

## 1. 目标和结论原则

测试和质量门禁的目标是证明变更在声明范围内正确、安全、兼容且可维护。测试数量或覆盖率不是唯一目标，证据必须与风险匹配。

“通过”只表示对应检查实际执行并成功；未执行、失败、超时、工具缺失和环境阻塞必须分别记录。

## 2. 测试选择

| 变更类型 | 优先验证 |
| --- | --- |
| 纯函数、转换、校验、状态机 | 单元测试和边界测试 |
| Controller/HTTP、API 客户端、序列化 | 接口/契约测试和错误路径 |
| Service、权限、事务、Repository | 服务测试、持久化集成测试和回滚路径 |
| Vue 组件、Composable、Store、路由 | 用户行为、状态转换、权限展示和错误交互测试 |
| 数据库、消息、缓存、外部服务 | 集成/契约测试、重复与失败测试、迁移验证 |
| 性能变更 | 固定口径基线、负载/Profiling、回归比较 |
| 升级迁移 | 编译、启动、核心流程、兼容性和回滚验证 |
| 纯文档或治理配置 | UTF-8、链接、结构、Registry/文档引用和 diff 检查 |

每次变更至少考虑：正常路径、非法输入、边界值、权限失败、依赖失败、重复操作、并发/竞态和回归路径中适用的部分。

## 3. 稳定测试

- 测试应隔离外部网络、时间、随机数、环境变量、全局状态和测试执行顺序。
- 不用固定睡眠掩盖竞态；使用可观察的完成条件、虚拟时钟或受控同步机制。
- 测试数据最小化、可读、脱敏且不依赖生产数据。
- 替身、Mock、Stub 和测试容器必须与真实边界一致，不能把所有依赖都 Mock 掉而失去契约验证。
- 失败断言应验证用户/系统可观察行为，不依赖无关的内部调用次数或脆弱的实现细节。
- 不吞掉测试异常，不在测试中修改开发者机器的系统配置、全局环境或未声明的外部资源。

## 4. 工具发现和环境

执行构建、测试、脚本或其他项目命令前：

1. 读取目标项目根目录的 `AGENTS.md` 和 `.dev-env.yaml`。
2. 按 `.dev-env.yaml` 验证 Java、Maven、Node 或 pnpm 路径和实际版本。
3. 只使用项目真实存在的 Maven 生命周期、`package.json` scripts、Lint、类型、测试、构建和架构检查。
4. 不安装依赖、不修改系统环境变量、不自动生成配置，不把猜测的命令当作验证。

目标项目没有可靠工具时，使用人工审查、定向脚本或测试证据补充，并把自动化缺失记录为告警或未执行。

## 5. 规范发现和指纹

`development-standards` 每次检查应发现以下来源并计算 SHA-256 指纹：

- `AGENTS.md`、`.dev-env.yaml` 和 `docs/开发规范/README.md`。
- `.editorconfig`、`pom.xml`、`package.json`、Lint/Prettier/TypeScript/CI 配置。
- 已发现的测试、构建、格式和质量命令。
- 当前任务明确提供且按 UTF-8 读取的用户规则。

编排任务将发现结果保存为 `standards-context` 和 `standards-fingerprint`；后续 `standards-check` 必须比较基线。规范来源发生变化时，重新发现最新来源并在报告中列出变化。

## 6. 检查顺序和自动纠正

推荐顺序：

1. 变更文件 UTF-8 检查和 `git diff --check`。
2. 目标项目已配置的格式、Lint 和类型检查。
3. 受影响模块的定向单元/集成/契约测试。
4. 变更涉及时执行全量测试、构建、Maven `verify` 或架构检查。
5. 重新检查工作区范围、生成文件、接口文档和交付证据。

默认只读。只有用户明确要求纠正时，才执行已知且可限定到变更文件的修复器；不运行任意 `--fix` 脚本、项目级全量格式化、依赖安装、迁移或部署。

## 7. 证据格式

每项检查至少记录：

| 字段 | 要求 |
| --- | --- |
| 检查 ID | 稳定、可引用 |
| 来源 | 配置文件、Skill、规范章节或工具 |
| 范围 | 变更文件、模块或全量项目 |
| 命令 | 实际执行的参数，不写未执行命令 |
| 退出码/状态 | 真实退出码或工具不可启动原因 |
| 证据 | 摘要、文件位置、测试名称或报告路径 |
| 结论 | 通过、阻断、告警、未知或未执行 |

命令输出应脱敏；不要把完整环境变量、令牌、生产数据或大段日志复制到 Artifact。

## 8. 本仓库门禁

本仓库是包含 `backend` 和 `frontend` 子项目的全栈 monorepo。Spring Boot/Vue 检查从仓库根目录识别对应子项目，并在子项目工作目录执行真实的 Maven/pnpm 命令。本仓库应执行：

```text
python -X utf8 .codex/skills/orchestrator/scripts/registry_tool.py validate
python -X utf8 -m unittest discover -s .codex/skills/orchestrator/tests -p "test_*.py"
python -X utf8 -m unittest discover -s .codex/skills/development-standards/tests -p "test_*.py"
python -X utf8 .codex/skills/development-standards/scripts/standards_tool.py check --root . --stack springboot --changed-from-git --full
python -X utf8 .codex/skills/development-standards/scripts/standards_tool.py check --root . --stack vue --changed-from-git --full
```

文档变更还应执行 `git diff --check`，检查链接和变更范围，并确认没有生成未授权的代码、Registry 或缓存文件。

## 9. 失败处理

- 工具返回非零退出码是失败，不得通过重跑覆盖原始结果。
- 工具无法启动、版本不匹配、路径缺失或超时是环境阻塞，应记录替代证据和剩余风险。
- 测试不稳定时先保留失败样本，区分产品缺陷、测试缺陷和环境问题；不能简单增加重试次数掩盖。
- 必要检查因环境阻塞无法完成时，交付结论不得写成完全通过。
- 规范指纹损坏、无法读取或基线与当前栈不匹配时阻断检查，不能复用旧基线。
