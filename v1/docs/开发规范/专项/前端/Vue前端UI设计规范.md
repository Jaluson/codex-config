# Vue 前端 UI 设计规范

## 1. 目标与适用范围

本规范提炼自当前管理后台用户管理页的实际设计，适用于 Vue 3 + TypeScript + Vite 前端中的后台页面、业务组件和 Element Plus 组件组合。

核心目标是建立“铺满当前页面、内容内部滚动、层次柔和、窄屏可用”的界面语言。新增页面应优先复用本规范和项目现有组件，不为单个页面引入独立的视觉体系。

## 2. 总体设计原则

- 页面使用固定视口布局，浏览器窗口不承担业务内容滚动；超出内容由应用内容区、列表区或侧栏内部滚动。
- 信息按“应用框架 → 页面工具栏 → 筛选/提示层 → 数据层 → 操作层”分层，不把所有内容直接堆在同一张白色卡片中。
- 通过浅色背景、低对比边框、柔和阴影和适度圆角建立层次，不使用大面积纯黑、强阴影或高饱和色制造层级。
- 桌面端优先保持稳定的横向结构；宽度不足时整体换行或切换为单列，不允许控件挤压、溢出或出现浏览器横向滚动条。
- 视觉层次不能牺牲语义、键盘操作、焦点可见性和错误可读性。

## 3. 页面框架与空间

### 3.1 视口和滚动

- 根页面使用视口高度布局，页面级 `html`、`body` 和 `#app` 禁止出现浏览器滚动条。
- 应用主布局使用 `height: 100vh`，同时兼容移动端动态视口高度 `100dvh`。
- Flex 子项涉及剩余高度时必须设置 `min-height: 0`；涉及横向收缩时必须设置 `min-width: 0`。
- 主内容栏使用 `overflow-y: auto`、`overflow-x: hidden`，表格等宽内容在自己的容器内处理横向滚动。
- 侧栏可以独立纵向滚动；滚动条应使用细窄、低对比的应用内样式，不能依赖浏览器默认粗滚动条。

### 3.2 动态铺满浏览器

- `html`、`body` 和 `#app` 共同形成无浏览器页面滚动条的可视区域；应用外壳以 `100dvh` 为目标高度，并提供项目已有的 `100vh` 兼容回退，使地址栏变化、窗口缩放和高低分辨率下的内容区持续铺满浏览器。
- 动态铺满由应用外壳与内容区的 Flex/Grid 剩余空间分配实现，不使用多层固定高度或脆弱的 `calc()` 链；需要测量容器时，优先使用 `ResizeObserver`，并在卸载时清理。
- 宽度和高度变化优先由 CSS 响应式规则处理；只有 CSS 无法表达的业务尺寸依赖才使用脚本测量，不能在滚动或渲染过程中反复同步读取布局并写回样式。

### 3.3 页面层级

页面推荐使用以下结构：

```text
应用外壳
├── 侧栏导航
└── 主区域
    ├── 顶部栏
    └── 内容栏
        ├── 页面标题与主要操作
        ├── 筛选/说明层
        └── 数据卡片
            ├── 卡片标题
            └── 独立数据层
                ├── 提示或错误信息
                ├── 表格/列表
                └── 分页与结果摘要
```

页面标题、筛选条件和数据列表应有清晰的间距和边界，避免标题、表单、表格全部直接贴合。

### 3.4 RBAC 管理页统一基准

- 当前“用户管理”页是 RBAC 用户、角色、权限资源和审计日志等管理页的唯一视觉与布局基准。相同职责区域必须复用该页面的层级、间距、色彩、圆角、边框、阴影、表格和分页表现，不能按单页另建近似但不一致的视觉方案。
- 管理页固定采用“页面工具栏 → 筛选或说明层 → 数据卡片”的骨架：工具栏包含 `h1` 与主要操作；筛选或说明层包含标题、简短说明和胶囊标签；数据卡片包含标题、总数标签、独立数据层以及分页结果摘要。没有筛选条件的页面仍保留说明层，不以大标题区替代。
- 筛选页使用与用户管理页相同的字段标签、控件宽度、查询/重置动作区和窄屏换行规则；列表页使用相同的表格边界、斑马纹、悬停反馈、空状态尺寸、分页背景和“显示 X–Y 条，共 N 条”摘要。
- 这类跨页面稳定模式必须放入 `frontend/src/styles.css` 的共享管理页规则中；页面 scoped style 只承载列宽、字段数量或业务语义等差异，不能覆盖共享的页面层级和视觉 token。共享规则调整后，必须同时检查全部受影响管理页。

## 4. 色彩、边框和层次

推荐使用项目现有的柔和蓝灰色系：

| 用途 | 建议值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#edf2f8` | 与白色内容层形成低对比背景 |
| 内容背景 | `#f7f9fc` | 主内容栏的柔和底色 |
| 卡片表面 | `#ffffff` | 主要承载内容 |
| 次级表面 | `#f8fafd` | 表格层、弹窗标题区、筛选层 |
| 普通边框 | `#e1e8f2` | 不使用纯黑边框 |
| 弱边框 | `#e8eef6` | 分隔线、表头和次要区域 |
| 主文字 | `#172033` | 标题和重要内容 |
| 次文字 | `#52617b` / `#71809a` | 标签、说明和摘要 |

- 卡片圆角通常使用 `16px–20px`；控件圆角通常使用 `10px`；标签和徽标可使用胶囊形圆角。
- 卡片阴影应轻量、扩散、低透明度，例如 `0 10px 28px rgb(55 76 108 / 8%)`。
- 同一层级的组件使用相同的圆角、边框和阴影，不在页面内混用多套强弱差异明显的卡片风格。
- 选中、悬停和焦点状态优先使用浅蓝背景或边框变化，避免大面积深色填充。
- 页面层级必须具有可辨识的递进：应用框架使用最弱背景与容器边界，工具栏通过标题和小型强调元素建立入口，筛选/说明层使用轻微渐变和浅阴影，数据卡片使用更明确的表面与阴影，表格层再以浅色内嵌容器区分。递进服务于信息优先级，不得仅靠堆叠卡片或加重阴影。

## 5. 表单与筛选层

- 筛选区域应作为独立的浅色面板，包含明确标题、简短说明和字段组，不让输入框直接漂浮在页面背景上。
- label 与输入控件必须有稳定的对齐关系；使用自然宽度或明确的统一宽度时，必须保证同组字段的视觉基线一致。
- 桌面端可采用横向排列；宽度不足时整体切换为多行或单列，禁止通过负边距、固定超宽或溢出隐藏掩盖问题。
- 输入控件必须设置 `min-width: 0`，固定宽度字段同时要提供窄屏覆盖规则。
- 查询、重置等操作应放在字段组末端并保持统一间距；重置按钮使用低强调样式，避免与主操作竞争。
- 表单应提供加载、禁用、校验错误和提交中状态；错误信息不能只依靠颜色表达。
- 新增或编辑/更新接口表单应在字段附近提供简短用途说明、`placeholder` 示例或约束提示；新增和更新模式的说明内容、字段可见性和校验反馈应保持一致。
- 可编辑文本输入框必须提供简洁、可操作的 `placeholder` 示例或提示，但不能用 `placeholder` 替代可见 `label`；只读或禁用展示框不添加误导性占位提示。
- 必填表单项必须显示清晰可见的 `*` 标记，并通过 Element Plus `required` 属性或校验规则表达；可选项不得显示 `*`，条件必填项只在条件成立时显示并校验标记。
- 弹窗表单使用独立内容区和底部操作区，标题、字段、取消和保存之间保持清晰的空间层次。

## 6. 表格与数据层

- 表格应放在独立的数据层容器中，使用浅色背景、内边距、圆角和低对比边框与外层卡片区分。
- 表格默认使用清晰表头、适度斑马纹、行悬停反馈和必要的列边框；数据较复杂时优先开启 `border`。
- 操作列不应堆叠过多按钮；编辑、角色、重置、状态和删除等操作可收纳至“更多”菜单，并继续遵守权限和当前用户保护规则。
- 表格加载时保持表头和容器结构稳定，使用加载遮罩或骨架屏，避免内容区域大幅跳动。
- 空状态至少区分“没有数据”和“筛选后无匹配结果”；筛选无结果时提供清空筛选入口。
- 分页区同时展示结果范围和分页控件；移动端允许分页控件换行或横向内部滚动。
- 宽表格只能在表格容器内部横向滚动，不能把页面整体撑宽。

## 7. 动效层级

- 路由与页面进入只使用短促的 `opacity` 和 `transform` 过渡，避免遮挡、长时等待或脚本驱动动画；离开和进入必须可中断。
- 管理页按“工具栏 → 筛选/说明层 → 数据卡片”以小幅错峰进入，延迟应短于用户可感知的等待阈值，不能对列表的每一行逐条播放入场动画。
- 悬停、选中和焦点使用边框、背景、阴影或极小位移表达层级变化；危险操作、错误和加载仍须保留文字、图标与 Element Plus 状态，不能只用动画表达。
- 所有非必要动效必须在 `prefers-reduced-motion: reduce` 下移除或显著缩短；动效不得改变焦点顺序、触发重复请求或影响键盘操作。

页面层级与动效的实现边界如下：

| 层级 | UI 责任 | 动效规则 |
| --- | --- | --- |
| 应用外壳 | 提供背景、侧栏、顶部栏和内容容器，不抢占业务内容注意力 | 仅允许导航悬停、激活态和轻量表面过渡；不对外壳整体循环动画 |
| 页面工具栏 | 建立当前页面入口，包含标题、主操作和小型强调元素 | 先进入；只使用透明度与不超过 `10px` 的纵向位移 |
| 筛选/说明层 | 解释页面目标、承载筛选条件或上下文提示 | 在工具栏之后进入；只可使用同类淡入上移，延迟应小于 `100ms` |
| 数据卡片 | 承载统计、列表与主要任务，视觉层级高于说明层 | 最后进入；允许轻量阴影和边框过渡，不得缩放或弹跳 |
| 表格/列表层 | 呈现稳定数据、空状态、加载和分页 | 不逐行播放入场动效；筛选、分页和刷新只使用局部 loading，保持内容位置稳定 |
| 弹窗/反馈 | 承载需要用户决策的短时任务 | 优先使用 Element Plus 默认动效；不得遮蔽焦点、阻止 Esc 或延迟可操作控件 |

- 动效时长通常为 `160ms–400ms`；延迟只用于页面层级递进，总累计不超过 `160ms`。不使用无限循环、闪烁、弹跳或大范围缩放作为装饰。
- 全局视觉和动效变量、关键帧以及跨页面选择器只能放在 `frontend/src/styles.css`；页面 scoped style 仅可补充具有业务语义的局部状态，且必须继承减少动态效果规则。

## 8. 视觉反馈

- 可操作控件至少应呈现默认、悬停、键盘焦点、按下、禁用和 loading 状态；反馈与操作位置和语义对应，不能仅通过颜色区分。
- 首次读取使用与最终内容结构接近的骨架屏；已加载数据的刷新、筛选和分页保留稳定内容并显示局部 loading。读取成功不产生成功通知，写入成功或失败只显示一次与操作对应的通知。
- 空状态必须区分“当前没有数据”和“筛选后无匹配”；后者提供清空或调整筛选的入口。错误状态提供重试、修正输入或其他可执行下一步，不能只显示技术错误文本。
- loading、骨架屏、遮罩和禁用状态应保留原有布局骨架，避免表格、表单、分页或弹窗在请求期间剧烈跳动，也不遮挡仍需操作的无关区域。
- 错误反馈说明下一步可执行动作，例如重试、清空筛选或修正字段；错误、成功和焦点状态需同时满足文本、图标或语义提示，不能只依赖颜色或动效。

## 9. 响应式与极端视口

- 响应式断点应在控件开始挤压前切换布局；不要等到文字重叠或按钮溢出后才处理。
- 窄屏时侧栏应保持文字可读，或采用明确的导航折叠方案；禁止使用不完整的文字截断制造乱码。
- 顶部栏中的用户信息和退出按钮允许换行，按钮必须始终可见、可点击且不超出容器。
- 低高度窗口应压缩非必要的标题说明、外边距和内边距，把可用高度优先给内容区。
- 极端宽度和高度下必须检查：侧栏文字、顶部操作、筛选字段、表格操作列、弹窗 footer、分页和空状态。
- 页面始终保持 `overflow-x: hidden` 的外层约束，并把真正需要的滚动交给对应内部容器。

## 10. 组件复用与实现约束

- 优先使用 Element Plus 的 `ElCard`、`ElTable`、`ElDialog`、`ElForm`、`ElEmpty`、`ElPagination` 和下拉菜单能力。
- 全局视觉规则放在 `frontend/src/styles.css`；页面特有的布局规则放在页面自身的 scoped style 中。
- 用户、角色、权限资源和审计日志等管理页应使用统一的 `management-page`、`page-toolbar`、`filter-panel`、`management-card`、`table-layer`、`pagination-container` 与 `result-summary` 结构；新增管理页优先复用这些共享类和 Element Plus 组件。
- 页面特有样式不得覆盖全局层级变量来制造新的颜色、圆角或阴影体系，除非有明确业务语义并记录原因。
- 组件改造应保持现有 API、权限判断、加载状态和键盘行为不变；视觉优化不能改变业务契约。
- 新增页面完成后，应至少在正常桌面宽度、窄屏、低高度和空数据状态下检查视觉层级与内部滚动。

## 11. 验收清单

- [ ] 页面没有浏览器横向或纵向滚动条，超出内容由应用内部容器滚动。
- [ ] 侧栏、顶部栏、筛选层、数据层和弹窗具有清晰且柔和的分层。
- [ ] 卡片、表格、表单和按钮使用统一的圆角、边框、阴影和交互反馈。
- [ ] 新增/更新接口表单提供字段说明和 `placeholder`；必填项显示 `*`，可选项不显示 `*`，条件变化后标记和校验同步更新。
- [ ] label、输入框、按钮和分页在桌面端对齐，在窄屏下稳定换行。
- [ ] 表格具备表头、边界、悬停、加载、空数据、无匹配和分页状态。
- [ ] 权限操作在收纳后仍可发现、可键盘操作，危险操作仍有确认机制。
- [ ] 低高度和极端宽度下没有按钮溢出、文字乱码、内容被顶出或布局撑破。
- [ ] 页面在尺寸变化时仍动态铺满可用区域，业务内容在内部滚动，未依赖脆弱的固定高度或重复脚本测量。
- [ ] 首次加载使用结构接近的骨架屏，局部刷新保留稳定内容；无白屏、剧烈跳动或重复通知。
- [ ] 空数据与无匹配可区分并提供下一步；成功、失败、loading 和控件状态具有与位置对应且非仅颜色的视觉反馈。
- [ ] RBAC 管理页已与用户管理页的工具栏、筛选/说明层、数据卡片、统计标签、表格数据层和分页摘要对齐；差异仅限明确的业务字段和操作。
- [ ] 页面各层级具有可辨识的递进表面与短促动效；动效只使用允许的属性与时序，在减少动态效果模式下仍保持完整状态反馈。
- [ ] 已执行项目实际存在的类型检查、Lint、测试和构建命令，并如实记录结果。
