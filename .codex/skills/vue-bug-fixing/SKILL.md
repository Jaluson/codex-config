# Vue 3 缺陷修复

## 目标

以可复现证据和明确的回归验收为依据，定位 Vue 3 前端缺陷的根因，实施范围最小且可回滚的修复。保持现有组件契约、路由、状态、API、视觉和运行约定，避免把排障扩大为无关重构或升级。

## 工作流程

### 1. 收集仓库和问题证据

- 先检查 `git status`、相关 diff、模块结构、`package.json`、锁文件、脚本、构建配置和相似实现，保留用户已有修改。
- 读取问题描述、复现步骤、浏览器控制台、网络请求/响应、堆栈、截图、时间线、浏览器和构建环境；区分事实、推测和缺失证据。
- 执行 pnpm、测试、构建或脚本前读取根目录 `AGENTS.md` 和 `.dev-env.yaml`，显式使用 UTF-8 读取配置，按 `frontend.package_manager` 使用 `pnpm`，不修改系统环境变量。
- 如果脚本联动后端构建，按 `.dev-env.yaml` 的 `development.java.home` 和 `development.maven.home` 为当前进程设置 `JAVA_HOME`、`MAVEN_HOME`；单独前端命令不猜测或替换这些路径。

### 2. 建立最小复现

- 优先使用现有失败测试、组件测试、路由流程或 E2E 用例复现；没有用例时用最小输入、页面路径和操作序列记录复现条件。
- 分离输入、响应式状态、生命周期、路由、Store、异步请求、缓存、浏览器差异和时序因素；记录命令、环境和结果。
- 无法稳定复现时，继续检查 props/emits、`watch`/`watchEffect`、组件卸载、重复请求、过期响应、列表 key、类型收窄和异常边界；不得用猜测替代结论。

### 3. 定位根因

沿用户事件到页面结果追踪首个错误行为：

`事件/路由 -> 组件输入 -> composable/Store -> API 客户端 -> 响应式更新 -> DOM/提示`

- 区分根因、放大因素和表面症状，检查最近变更、条件渲染、异步竞争、代理对象解构、事件名、空值和错误转换。
- 对接口问题核对请求方法、参数、响应结构、状态码、取消和重试；不要把后端错误静默转换为成功状态。
- 对视觉或交互问题同时检查语义 HTML、CSS 作用域、焦点、键盘事件、视口和无障碍状态。

### 4. 实施最小修复

- 先修复根因，遵循现有组件、composable、Store、路由、API 和样式约定；不顺手升级依赖、重排无关代码或引入新抽象。
- 为异步操作补齐加载、失败、取消和卸载清理；避免以增加无界延时、吞异常或强制刷新掩盖时序问题。
- 保持 props、emits、slots、路由参数、Store 公共状态/动作、API 契约和本地存储兼容；确需变更时明确影响和迁移方式。

### 5. 补充回归测试

- 添加能稳定复现原问题的最小测试，遵循仓库已有测试工具；无既有约定时优先考虑 Vitest + Vue Test Utils，但不擅自安装依赖。
- 测试成功、边界、非法输入、异常映射、重复操作、路由变化、异步过期响应、组件卸载和相关历史回归。
- 测试应先在原缺陷条件下失败，再在修复后通过；无法做到时提供等价的复现证据并说明限制。

### 6. 分层验证和交付

- 先运行受影响测试，再按 `package.json` 实际脚本执行类型检查、lint、test 和 production build；E2E 仅使用仓库已有的 Playwright/Cypress。
- 检查控制台警告、网络请求、错误提示、键盘操作和不同视口；确认修复没有引入新的状态或权限问题。
- 检查 `git diff`、`git diff --check` 和文件状态，汇报现象、根因、修复、回归测试、执行命令、通过/未执行项和残留风险。

## 失败处理与边界

- 测试、依赖、浏览器、环境变量、后端接口或外部服务不可用时，保留证据，提供静态检查并明确不能证明的内容。
- 不为了让测试通过而放宽断言、隐藏错误、关闭校验、绕过权限或改变用户可见错误语义。
- 如果只能提出根因假设，按假设交付并列出需要补充的日志、复现条件或观测指标。
- Nuxt、SSR、Nitro 和 Vue 2 专项迁移不属于本 skill；遇到超出范围的请求先明确边界。
- 所有新增或修改文本使用 UTF-8；不执行无关的破坏性命令。

## 编排契约

- 由 `$orchestrator` 调用时，按 Workflow Registry 指定的阶段执行，不重复执行其他阶段；直接调用本 skill 时仍执行完整工作流程。
- 支持阶段：`evidence`、`reproduce`、`diagnose`、`fix`、`regression-test`、`verify`。
- 读取当前 run 中注册的输入 Artifact，将阶段证据写入注册的输出 Artifact；不得使用未声明的路径传递上下文。
- 阶段失败时保留原始证据并报告阻塞，不通过放宽断言、隐藏错误或跳过校验掩盖失败。
