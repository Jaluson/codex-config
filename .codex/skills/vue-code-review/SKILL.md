# Vue 3 代码审查

## 目标

基于工作区事实、变更 diff、测试和运行约束，发现会影响正确性、安全性、可访问性、性能、兼容性或可维护性的具体问题。默认只读，不修改代码、配置、测试、锁文件或格式化文件。

设计与实现时遵守[通用设计与实现方向](../通用设计与实现方向.md)。

## 审查流程

### 1. 建立审查上下文

- 先检查 `git status`、目标 diff、提交范围、模块边界、`package.json`、锁文件和用户已有修改；不把无关未提交内容当作待审代码。
- 读取相关 SFC、composable、Store、路由、API 类型/客户端、样式、配置、调用方、测试和 CI，理解变更前后的行为。
- 执行只读测试、构建或静态检查前读取 `AGENTS.md` 和 `.dev-env.yaml`，显式按 UTF-8 读取，使用配置的 `pnpm`，不修改系统环境变量。
- 如果只读检查联动后端构建，按 `.dev-env.yaml` 的 `development.java.home` 和 `development.maven.home` 为当前进程设置 `JAVA_HOME`、`MAVEN_HOME`；单独前端检查不猜测或替换这些路径。

### 2. 按风险检查

- 编译与类型：检查导入别名、类型收窄、空值、`any`、props/emits/slots 契约、模板类型、事件参数、异步返回值和构建配置。
- 运行时正确性：检查响应式引用与解构、computed/watch 依赖、生命周期清理、重复/过期请求、列表 key、条件渲染、路由参数和 Store 一致性。
- 用户体验与可访问性：检查语义 HTML、label、ARIA、键盘和焦点、错误/加载状态、移动端布局、颜色对比和动态内容通知。
- 安全性：检查 `v-html`、不可信 URL、模板注入、XSS、令牌和敏感数据持久化、日志泄露、权限仅靠前端隐藏以及第三方脚本边界。
- API 与兼容性：检查请求/响应字段、错误处理、缓存、URL/localStorage 格式、公共 props/emits/slots、路由和 Store API 是否破坏调用方。
- 性能与资源：检查不必要渲染、深层响应式、昂贵 computed、监听器泄漏、大列表、重复请求、路由懒加载、包体和静态资源。
- 测试：检查新增路径、失败路径、边界、回归、组件交互和路由/Store/API 集成是否有能证明行为的测试。

### 3. 输出可执行发现

每条发现都包含：

- 严重级别：阻断、高、中或低。
- 文件路径和行号或最小代码位置。
- 现象、触发条件、证据和实际影响。
- 建议的修复方向，以及需要补充的测试或验证。

优先报告可验证、可修复的问题；不要用个人风格偏好替代缺陷。若没有发现问题，说明审查范围、验证方式和仍未覆盖的风险，不输出只有赞扬的报告。

### 4. 验证审查结论

- 可在不改文件的前提下运行已有定向测试、类型检查、构建或静态分析；只使用 `package.json` 中实际存在的脚本。
- 不运行格式化器、代码生成、依赖安装、迁移或会覆盖文件的命令；不为验证生成临时代码。
- 对无法运行的检查记录环境阻塞和替代证据；最后用 `git status`、`git diff` 和 `git diff --check` 确认审查过程没有产生仓库变更。

## 变更权限与边界

- 用户明确要求“审查并修复”时，先保留完整审查结论，再按授权转入 `vue-bug-fixing` 或 `vue-feature-development` 的验证要求。
- 不因个人偏好要求无收益的重写、依赖升级、全量格式化或组件库替换。
- Nuxt、SSR、Nitro 和 Vue 2 项目需要单独的审查约束；本 skill 默认面向 Vue 3 + TypeScript + Vite SPA。
- 所有新增或修改文本使用 UTF-8；不执行无关的破坏性命令。

## 开发规范

- 直接调用本 skill 时，先读取项目根目录 `docs/开发规范/README.md`（存在时）和项目已有质量工具；不凭个人偏好添加风格规则。
- 由 `$orchestrator` 调用时，规范检查由 `development-standards` 阶段统一执行，本 skill 只遵循其报告和本任务专属约束。

## 编排契约

- 由 `$orchestrator` 调用时，按 Workflow Registry 指定的阶段执行，不重复执行其他阶段；直接调用本 skill 时仍执行完整审查流程。
- 支持阶段：`context`、`risk-review`、`findings`、`verify`、`report`。
- 读取当前 run 中注册的输入 Artifact，将审查证据和报告写入注册的输出 Artifact；审查阶段保持只读。
- 阶段失败时保留审查范围、证据和环境阻塞，不用风格偏好替代可验证发现。
