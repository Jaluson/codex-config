# 接口文档维护

## 目标和范围

维护目标项目根目录下的唯一接口文档：

`docs/接口文档/${模块}-${功能}.md`

- 仅处理对外可观察的 HTTP/Web API，包括 REST、Controller 路由和前端调用所依赖的 HTTP 契约；内部方法、数据库内部结构和未对外暴露的实现不单独建立接口文档。
- 文档必须描述当前真实契约；历史差异写入同一文件的“修订记录”，不得创建日期版、版本版、备份版或副本文件。
- 直接调用本 Skill 时执行完整流程；由 `$orchestrator` 调用时只执行 Registry 指定的 `inspect`、`update` 或 `verify` 阶段，并使用当前 run 的 Artifact 交接。

设计与实现时遵守[通用设计与实现方向](../通用设计与实现方向.md)。

## 工作流程

### 1. 识别接口变更和文档 (`inspect`)

- 读取目标项目的 `AGENTS.md`、现有文档约定和当前 `git status`/diff；保留用户已有修改。
- 从路由、Controller、请求/响应 DTO、校验、异常映射、鉴权配置、前端 API 客户端和相关测试中确认接口实际行为。
- 判断是否存在对外契约变化：新增、删除或修改 HTTP 方法、路径、查询/路径/请求头/请求体、响应字段、状态码、错误语义、鉴权、幂等性或兼容性都算接口变化。
- 使用仓库已有的模块名和功能名定位文档，优先查找精确的 `docs/接口文档/${模块}-${功能}.md`；不存在时准备创建。
- 检查目录内是否有同一模块与功能的日期后缀、版本后缀、备份或重复文档。无法明确归属时停止并报告候选文件，不静默覆盖。
- 将接口变化、候选文档、目标路径和需要保留的历史记录写入编排 Artifact `api-documentation-plan`。

### 2. 更新唯一接口文档 (`update`)

- 创建或原地更新 `docs/接口文档/${模块}-${功能}.md`，不得改变规定目录和文件命名。
- 按 [接口文档模板](references/api-document-template.md) 保留接口概览、通用约定、接口详情、错误/兼容性说明和修订记录；可以保留项目已有的有效内容，但必须补齐当前契约所需字段。
- 每个接口至少记录用途、HTTP 方法与路径、鉴权要求、请求参数/请求体、成功响应、失败状态码与错误格式、示例和兼容性注意事项；无法从仓库确认的内容标为待确认，不凭空编造。
- 首次建立使用 `R1`；后续每次实际契约变更递增修订号，并在修订记录中写入 `修订号、日期、修改内容、影响接口、原因/关联任务`。修订号不是 HTTP API 版本号。
- 正文只呈现当前版本的接口行为；不要为历史版本复制一套接口章节。若接口本身有 `/v1`、`/v2` 等路径，仍在同一模块-功能文档中说明。
- 对确认属于同一模块与功能的旧版本/副本文件，先将有效内容和修订历史合并到规范文件，再删除过期副本；删除前必须确认内容已保留。候选关系不明确时阻塞并请求确认。
- 不写入令牌、密码、生产数据或未经脱敏的请求/响应；示例使用安全的占位值。
- 将实际文件路径、采取的创建/更新/合并动作和修订号写入 `api-documentation-change`；无接口变化时明确记录“无需更新接口文档”。

### 3. 验证接口文档门禁 (`verify`)

- 对照实现和测试核对 HTTP 方法、路径、参数名称/类型/必填性、响应结构、状态码、错误语义、鉴权和示例，不把推测当作契约。
- 确认同一模块与功能只有一个规范文档，文档正文没有过期接口定义，修订记录包含本次变更；确认新增或修改的接口没有遗漏文档。
- 检查 `git diff`、`git diff --check` 和文档编码；只报告实际执行的检查结果。
- 发现文档与代码不一致时，先修正文档；无法确认真实行为时阻塞后续实现或交付。
- 在编排 run 中生成 `api-documentation-report`，记录文档路径、接口变化结论、校验项、通过/失败/未执行项和残留风险。

## 编排契约

- 支持阶段：`inspect`、`update`、`verify`。
- `inspect` 消费代码变更摘要并产出文档计划；`update` 消费计划并实际维护目标项目文档；`verify` 消费更新结果并产出门禁报告。
- 阶段失败时保留已生成 Artifact 和原始错误；不得把“无接口变化”或“未执行校验”报告为接口文档已更新。
- 直接调用时仍必须完成识别、更新和验证，即使任务来自 Spring Boot 或 Vue 的其他叶子 Skill。

## 必须遵守的边界

- 不把接口文档拆分为按日期、版本或提交保存的多份最新文档。
- 不为了补齐文档而改变代码契约、状态码、权限或数据结构；代码与既有测试是事实来源。
- 不覆盖用户已有修改，不执行与接口文档无关的全量格式化或破坏性命令。
- 所有新增或修改的文档使用 UTF-8。
