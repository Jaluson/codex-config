# Spring Boot 代码审查

## 目标

基于工作区事实、变更 diff、测试和运行约束，发现会影响正确性、安全性、数据一致性、兼容性、可靠性或可维护性的具体问题。默认只读，不修改代码、配置、测试或格式化文件。

## 审查流程

### 1. 建立审查上下文

- 先检查 git status、目标 diff、提交范围、模块边界和用户已有修改；不把无关未提交内容当作待审代码。
- 读取相关接口、调用方、实体、迁移、配置、权限、消息契约、外部客户端和测试，理解变更前后的行为。
- 执行测试、构建或静态检查前读取 .dev-env.yaml，使用其 Java 和 Maven 路径作为当前进程默认值，并记录实际版本。

### 2. 按风险检查

- 先检查编译、启动、路由、参数校验、异常状态码、空值、边界、事务和并发正确性。
- 检查认证授权、敏感数据、注入、反序列化、日志泄露、文件或网络访问及错误信息暴露。
- 检查 JPA 或 JDBC 查询、索引、N+1、事务传播、锁、幂等、缓存一致性、消息重复消费和外部调用超时。
- 检查 API、数据库、配置、消息和序列化兼容性，以及 Spring 代理、反射、AOP、Jackson 和 JDK 约束。
- 检查测试是否能证明新增路径、失败路径、边界和回归；指出缺失测试的具体风险。

### 3. 输出可执行发现

每条发现都包含：

- 严重级别：阻断、高、中或低。
- 文件路径和行号或最小代码位置。
- 现象、触发条件、证据和实际影响。
- 建议的修复方向，以及需要补充的测试或验证。

优先报告可验证、可修复的问题；不要用风格偏好替代缺陷。若没有发现问题，说明审查范围、验证方式和仍未覆盖的风险，不输出只有赞扬的报告。

### 4. 验证审查结论

- 可在不改文件的前提下运行已有定向测试、构建、静态分析或查询；不要为审查生成或提交临时代码。
- 对无法运行的检查记录环境阻塞和替代证据。
- 用 git diff、git diff --check 和文件状态确认审查过程没有产生仓库变更。

## 变更权限与边界

- 默认只读；不要运行格式化器、代码生成、迁移或会覆盖文件的命令。
- 用户明确要求“审查并修复”时，先保留完整审查结论，再按用户授权实施修复，并转入缺陷修复或功能开发的验证要求。
- 不因个人偏好要求无收益的重写、依赖升级或架构替换。
- 所有新增或修改文本使用 UTF-8；不执行无关的破坏性命令。

## 开发规范

- 直接调用本 skill 时，先读取项目根目录 `docs/开发规范/README.md`（存在时）和项目已有质量工具；不凭个人偏好添加风格规则。
- 由 `$orchestrator` 调用时，规范检查由 `development-standards` 阶段统一执行，本 skill 只遵循其报告和本任务专属约束。

## 编排契约

- 由 `$orchestrator` 调用时，按 Workflow Registry 指定的阶段执行，不重复执行其他阶段；直接调用本 skill 时仍执行完整审查流程。
- 支持阶段：`context`、`risk-review`、`findings`、`verify`、`report`。
- 读取当前 run 中注册的输入 Artifact，将审查证据和报告写入注册的输出 Artifact；审查阶段保持只读。
- 阶段失败时保留审查范围、证据和环境阻塞，不用风格偏好替代可验证发现。
